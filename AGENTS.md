# AGENTS.md — правила работы в этом репозитории

Проект: решение задачи трека **«Торговля»** хакатона HackAlem AI (Астана, 23.09.2026).
Команда: 2 человека. Окно разработки: 13:00–18:00, жёсткий дедлайн.
Этот файл — закон. Если инструкция в чате противоречит ему, скажи об этом и спроси.

## Главное правило

**Работающее демо важнее красивого кода.** Любой выбор решается вопросом:
«это увеличит шанс, что в 17:50 на проекторе всё отработает без ошибки?»
Если нет — не делаем.

## Два дисквалификационных требования (важнее любой фичи)

1. **Чистый клон должен запускаться по README чужим человеком.** Не запустился — проект снят.
2. **Проект должен полностью работать без наших личных аккаунтов и API-ключей.**
   Поэтому в коде всегда есть `DEMO_MODE=1` (по умолчанию!), который отдаёт
   заранее записанные ответы LLM из `fixtures/` и не требует сети.
   `DEMO_MODE=0` + `OPENAI_API_KEY` включает живой режим. Оба режима обязаны работать.

## Стек (зафиксирован, не обсуждается)

- Backend: **Python 3.12 + FastAPI + SQLite** (файл `data/app.db`, создаётся сидом).
- Зависимости: `uv` (`pyproject.toml`), fallback `requirements.txt`.
- LLM: OpenAI SDK, **только structured outputs** (Pydantic-схемы), температура 0.
  Каждый вызов проходит через `app/llm.py` с: кэшем в `fixtures/`, ретраем, таймаутом
  и детерминированным rule-based фолбэком. Приложение **никогда** не падает из-за LLM.
- Frontend: **Vite + React + TypeScript + Tailwind**, собирается в `web/dist`.
  `web/dist` **коммитится в репозиторий**, FastAPI отдаёт его как статику.
  Смысл: проверяющему не нужен Node — `pip install` + `uvicorn` и всё работает.
- Графики: Recharts. Иконки: lucide-react. Никаких CDN-зависимостей в рантайме.
- Запуск одной командой: `uv run hack serve` (и дублирующий `docker compose up`).

Запрещено: микросервисы, Kafka, Celery, Redis, Postgres, Docker-в-Docker, auth/регистрация,
миграции Alembic, монорепо-тулинг, GraphQL, тесты ради тестов, рефакторинг «на будущее».

```
CREDITS.md      все сторонние компоненты, лицензии, датасеты (п. 5.4.4)
```

## Протокол работы агента

1. **Сначала план.** Для любой задачи больше 15 строк — сперва `/plan`: что меняем,
   какие файлы, как проверим. Ждёшь «го» от человека. Не начинаешь код без плана.
2. **Микро-итерации.** Один заход = одна вертикально работающая фича
   (данные → endpoint → UI → видно на экране). Не делай «сначала весь бэк, потом весь фронт».
3. **Проверяй сам, не спрашивай человека.** После каждого изменения:
   `uv run hack seed && uv run hack serve` и проверка эндпоинта через `curl`,
   для UI — Playwright MCP: открыть страницу, кликнуть сценарий, снять скриншот.
   Сломалось — чини сам, не отдавай человеку красный экран.
4. **main всегда зелёный.** Не коммить неработающее. Если фича не доделана за 25 минут —
   откатись к рабочему состоянию и скажи об этом.
5. **Каждый час** (в :55) — коммит + запись в `PROGRESS.md`: что сделано, что видно на экране.
   Формат коммита: `H2: агент считает упущенную выручку по SKU`.
6. **Границы файлов.** Участник A трогает `app/`, `data/`. Участник B — `web/`, `docs/`, `README.md`.
   Никогда не редактируй файлы вне своей зоны без явной просьбы — иначе конфликты слияния.
7. **Пиши в `docs/codex-log.md`** одну строку на каждую крупную задачу: промт → что сделал.
   Это доказательство использования Codex для технических экспертов.

## Стиль

- Русский язык в UI, сообщениях об ошибках, README и комментариях. Код и идентификаторы — английский.
- Деньги — в тенге (`₸`), формат `1 234 567 ₸`. Даты — `ДД.ММ.ГГГГ`.
- Никаких заглушек `TODO`, `coming soon`, кнопок-пустышек. Кнопка есть — она работает.
- Никаких моков в UI, если данные можно посчитать по-настоящему из SQLite.

## Done-критерий любой задачи

Задача закрыта, только когда: код работает в чистом клоне → видно в браузере →
описано в README → закоммичено. Всё остальное — не сделано.
