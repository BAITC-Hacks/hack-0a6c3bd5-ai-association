## Граница текстового подтверждения для внешних клиентов

Прямой `POST /api/chat` с «да добавь» подтверждает последнее показанное предложение **всей cookie-сессии**, без ID в теле chat-запроса. Воспроизведено: предложение на 2 шт → новое на 3 шт → прямое «да добавь» подтверждает 3 шт. Если внешние клиенты используют одну сессию одновременно, им нужно подтверждать именно показанное ими предложение через **`POST /api/proposals/{id}/confirm`**.

Текущий интерфейс уже использует подтверждение конкретного ID, включая текстовое «да». Это ограничение прямого chat API не означает обход проверки цены/остатка или права владения предложением.

После проверки runtime-коммита `f2b4953` повторно записан настоящий браузерный сценарий: скачанный из приложения PDF → конфликт 160/250 А → исключение строки → предложение → явное подтверждение → корзина → перезагрузка. Проверочные запросы подтвердили пустую корзину до согласия и **2 шт / 122 000 ₸** после него; ошибок JavaScript и внешних запросов — 0.

[Видео](assets/kontur-demo.mp4): **72,70 с**, 1440 × 1000, H.264, 1 773 710 байт, без озвучки. Русские субтитры встроены в MP4 и приложены как [SRT](assets/kontur-demo.srt). Кадры конфликта и подтверждения просмотрены; текст и суммы читаются. Видео относится к runtime-коду `f2b4953`, воспроизведённому в macOS-клоне. Перенос backend-изменений и повторная проверка интегрированного `3757794` описываются отдельно.

Удалены неиспользуемые стили первого прототипа, старые макеты и рабочие памятки. Итоговая документация описывает действующий интерфейс; исторический журнал сохранён. Локальные Markdown-ссылки проверены, `.env`, БД и кэш провайдера не отслеживаются Git; поиск строк, похожих на ключи API, в отслеживаемых текстовых файлах совпадений не дал.
