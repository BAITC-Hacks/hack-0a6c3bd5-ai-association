# Дизайн «Контура»

Рабочее приложение закупщика: запрос или файл → проверка каталога → предложение → явное подтверждение → серверная корзина. Интерфейс получает данные FastAPI; формат обмена описан в [API-CONTRACT.md](API-CONTRACT.md), продуктовый сценарий — в [SPEC.md](SPEC.md).

## Путь пользователя

- `/` — подбор с ассистентом. Начать можно с описания запроса или загрузки списка; рядом доступны конкретные примеры вопросов и поиск каталога.
- `/?view=catalog` — серверный поиск по названию/артикулу, пагинация, выбор склада и карточка товара. «Обсудить товар» передаёт точный артикул в чат.
- `/?view=upload` — один файл, редактируемые строки и результат проверки на том же экране. Расхождение можно исправить или исключить без перехода в чат. Подробный паспорт доступен отдельным действием.
- `/cart` — подтверждённые позиции текущей анонимной сессии. Изменение количества, удаление и очистка создают предложение, которое также требует подтверждения.

Общий указатель показывает этапы «Запрос или файл», «Проверка», «Подтверждение». До подтверждения пользователь видит, какой станет корзина; после успешной операции экран файла сообщает об обновлении и предлагает открыть корзину. На телефоне навигация расположена снизу, актуальное предложение имеет отдельную панель действия. Кнопка поиска и Ctrl+K / ⌘K фокусируют поиск каталога.

## Визуальная система

Тёплый бумажный фон, тёмный текст, тонкие границы и один оранжевый акцент выделяют действие. Компоновка напоминает рабочий лист закупщика: артикулы, количества и источники важнее декора.

| Элемент | Текущее решение |
|---|---|
| Основной текст | Локальный вариативный Onest |
| Заголовки и знак | Локальный вариативный Unbounded |
| Артикулы и служебные подписи | Локальный IBM Plex Mono, 400/500 |
| Холст / поверхность | `#f2efe8` / `#ffffff` |
| Основной / вторичный текст | `#1b1813` / `#3c352c` |
| Основное действие | `#d2410e`, активное состояние `#a83209` |
| Границы | `#ddd6c7` |
| Подтверждение / внимание | `#2c6a4a` / `#8a5a00` |

Собственные React-компоненты и CSS, Tailwind через Vite; готового UI-кита нет. Знак нарисован CSS/SVG, иконки — Lucide. Motion и NumberFlow оформляют переходы и серверные суммы; настройка уменьшения анимации учитывается. Шрифты, иконки, образцы и лицензии включены локально, CDN при работе не нужен.

Порядок CSS в `web/src/main.tsx`: `styles.css` → `catalog.css` → `commerce.css` → `checkout.css` → `upload.css` → `kontur.css`. Первый файл содержит общую основу, последний — типографику и текущие блоки пути. Перестановка может изменить размеры, адаптацию и оформление диалогов.

## Данные и основания ответа

Первый экран не придумывает цену или остаток до ответа API. Текст сервера сопровождается источником: `fixture` — записанный ответ, `rules` — проверка правилами, `openai` — ответ с участием модели. Дата и происхождение снимка остаются видимыми; три синтетические позиции отмечаются как учебные.

Паспорт показывает ожидаемое значение, фактическое значение и статус `match`, `conflict` или `unknown`. Противоречащие описание и свойства не объединяются с потерей различий. Исходные поля раскрываются отдельно. Паспорт с конфликтом открыт; остальные подробности можно раскрыть. Неизвестное значение `null` показывается как отсутствие данных, известный ноль — как нулевой остаток.

Карточки берут товар, цену, склад, локальное и общее наличие из API. Склад исторического ответа не подменяется текущим выбором. Отсутствующие изображения и сертификаты не заменяются вымышленными; документ открывается только при допустимом локальном пути.

## Файл и черновик

Поддерживаются XLSX, DOCX, PDF с текстовым слоем и JPEG; до 10 MiB, 50 строк, 10 страниц PDF. Учебные образцы доступны рядом с загрузкой. Для JPEG без внешнего распознавания работает точный поставляемый образец; произвольные фотографии требуют доступного live OCR.

Пользователь проверяет товар, целое положительное количество и единицу `шт`/`м`, исключает лишние строки. Исходные `line_id` сохраняются. Любая проблемная включённая строка блокирует предложение по всему списку. Черновик переживает переходы между экранами; перезагрузка его не восстанавливает.

В `web/public/examples` находятся только учебные копии `fixtures/uploads/sample.*`. Пользовательские файлы остаются в SQLite своей сессии и не публикуются как статика. Текст документа — данные, а не разрешение выполнять действия.

## Обязательные гарантии

- Кнопка подтверждения относится только к актуальному `latest.proposal`: статус pending, требование подтверждения, выбранный склад и действующий срок. Исторические предложения не получают активных кнопок.
- «Проверить и подтвердить» открывает окно с конкретным ID, составом, складом и серверной суммой. Изменение корзины выполняется только после явного согласия; сервер повторно проверяет условия.
- Количество в предложении — конечное количество строки; 0 удаляет её. Неуказанные позиции сохраняются. Суммы берутся с сервера.
- Текстовое подтверждение в UI привязано к показанному ID через endpoint подтверждения. Модель не даёт разрешение менять корзину.
- Правка документа, новый файл или смена склада снимают старое предложение в UI. Серверная отмена предложений при работе с документами описана в [ARCHITECTURE.md](ARCHITECTURE.md).
- После потери ответа повтор использует прежний UUID и исходное тело. Пока операция выполняется, повторные действия и редактирование блокируются.
- Корзина хранится на сервере с анонимной HttpOnly cookie и переживает перезагрузку. История интерфейса остаётся в памяти.
- Это локальная корзина демонстрационного приложения: заказ, оплата и резервирование в ekt.kz не выполняются.

Проверки должны охватывать клавиатуру и фокус, Escape, ошибки с повтором, узкий экран 390 px и полный путь от файла до сохранённой корзины. Актуальные результаты — [FINAL-QA.md](FINAL-QA.md); запуск и сборка — [README](../README.md). Готовый `web/dist` входит в Git.
