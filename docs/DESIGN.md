# Дизайн «Контура»

Документ описывает интерфейс в `web/`: основной каталог H1, подключённый к FastAPI/SQLite, и отдельное учебное «Демо подбора». Формат обмена задан в [API-CONTRACT.md](API-CONTRACT.md). Проверки каталога и история проверок дизайн-прототипа перечислены раздельно; H2 и LLM пока не реализованы.

## Замысел

«Точный подбор. Спокойная закупка.» — рабочая область закупщика, где переписка, основания решения и состав комплекта видны вместе. Покупатель должен различать три действия: получить рекомендацию, проверить её и подтвердить изменение корзины.

Главный экран `/` и адрес `/?view=catalog` открывают каталог: поиск и выбранный склад над карточками товаров, пагинация внизу, подробности в диалоге. Кнопка поиска и `Ctrl+K` / `⌘K` переводят пользователя к поисковому полю API-каталога.

В отдельном «Демо подбора» (`/?view=preview`) на широком экране слева расположена навигация, в центре — чат и паспорт подбора, справа — состав, количество, цена и подтверждение. Панель комплекта показывает состояние решения: проверка, готовность к подтверждению, подтверждённый комплект. `/cart` остаётся локальной учебной корзиной этого демо, без интеграции с каталогом H1.

Иерархию создают типографика, свободное пространство, тонкие границы и один синий акцент. Янтарный означает расхождение или нехватку, зелёный — совпадение проверяемых значений. Цвет поддерживается текстом, символом предупреждения или галочкой.

## Визуальные правила

| Элемент | Текущее решение |
| --- | --- |
| Основной шрифт | Manrope, локальные латинские и кириллические начертания 400–800 |
| Артикулы, метки, служебные подписи | IBM Plex Mono, локальные начертания 400 и 500 |
| Фон | `#f6f7fa`, белые рабочие поверхности |
| Основной текст | `#1d2b43`; вторичные тексты имеют отдельные оттенки по назначению |
| Действие | Синий `#315cea` |
| Разделители | `#e7eaf1` |
| Подтверждение / внимание | Зелёный `#31816a` / янтарный `#a56827` |
| Геометрия | Тонкие рамки, умеренное скругление, компактные строки сравнения |
| Иконки | Lucide React, тонкий единый штрих |

Стили находятся в `web/src/styles.css`; Tailwind подключён через Vite, композиция и внешний вид реализованы собственным CSS и React-компонентами. Готовая тема Material, Ant Design или shadcn не используется.

Знак «Контур» состоит из трёх CSS-полос. В «Демо подбора» иллюстрации выключателей построены из CSS-блоков: корпус, переключатели, контакты и условные подписи. Это схематические изображения, а не фотографии, чертежи или доказательство характеристик товара. Каталог H1 принимает только локальные изображения; когда их нет, показывает иконку упаковки с подписью «Изображение не предоставлено». Сторонние фотографии и удалённые assets не требуются.

## Каталог H1: происхождение и состояния данных

`CatalogPanel.tsx` получает склады, список и карточки через `api.ts`. В SQLite загружены 10 сохранённых карточек ekt.kz и одна синтетическая позиция для неизвестных значений. Это ограниченный offline-набор, не полный каталог и не live-данные. У снимков `source=demo_fixture`; источник ekt.kz указан через `source_url`, время сохранения — через `captured_at`. Единица для демо задана явно и отражена в свойстве `demo.unit_override`.

Выбор склада заполняется из `/api/warehouses`: Астана («Нур-Султан» в исходных данных), Алматы и Шымкент. Поиск по артикулу и названию выполняет сервер; строка ограничена 200 символами, запрос отправляется после короткой паузы. На странице до 6 карточек, смена запроса или склада возвращает к первой странице. Внутренний числовой ID товара не заменяет строковый артикул в поиске.

Карточка открывает отдельный запрос `/api/products/{id}` с выбранным `warehouse_id`. В деталях показаны цена за единицу, минимум, локальный остаток, общий остаток, описание, свойства вместе с полями источника, документы и дата снимка. Описание и свойства не сливаются: для `200300285_` остаются и 160 А в тексте, и 250 А в `NOMINALNYY_TOK`. H1 сохраняет и показывает сведения, но ещё не выполняет автоматический подбор.

Отсутствие значения оформлено отдельно от подтверждённого нуля: `null` цены — «Цена не указана», `null` остатка — «Нет данных», `null` минимума — «Не указано»; нулевой остаток — «0 … — нет в наличии». Например, `030300435_` имеет 0 шт. в Астане и 10 310 шт. всего: общий остаток не обещает доступность на выбранном складе. Синтетическая `000-DEMO-UNKNOWN` сохраняет неизвестные значения, не превращая их в нули.

При загрузке, ошибке сети и пустом результате показываются самостоятельные состояния. Ошибка даёт повторить запрос; пустой поиск — сбросить строку. Запросы при смене параметров отменяются, предыдущий результат не выдаётся за данные нового склада. При отсутствии документов текст сообщает, что наличие сертификата не подтверждено; внешний документ без локальной копии не изображается доступным offline.

## Паспорт в отдельном демо подбора

Главная часть сценария — сравнение «параметр → в запросе → в каталоге». Для учебного запроса на 160 А показываются:

- Номинальный ток: 160 А в запросе, 250 А в структурированной характеристике и отдельная подпись «в описании — 160 А».
- Количество полюсов: 3 в запросе и в учебной карточке.
- Остаток: запрошенное количество рядом с наличием на выбранном складе.

Ток подсвечивается как неразрешённое противоречие. Вкладка «Данные источника» и отдельное окно сохраняют оба значения и объясняют, почему нельзя выбрать одно наугад. Реальное наблюдение при подготовке проекта послужило основой сценария; актуальность каталога в этом прототипе не проверяется.

Проверка характеристик отделена от наличия. Совпадение тока и числа полюсов не означает, что выбранного количества хватает. При переключении склада меняются остатки и доступность подтверждения; при изменении количества пересчитывается итог.

## Учебные данные и взаимодействия демо

`web/src/design-data.ts` содержит три учебные позиции: исходную с конфликтом, аналог на 160 А и позицию на 100 А. Все цены и остатки предназначены для проверки интерфейса, не являются текущими предложениями магазина и не поступают из SQLite.

Этот набор используется только в демосценарии чата и подтверждения. Основной каталог и глобальный поиск работают с API и не показывают учебный аналог как реальный товар источника.

Чат обрабатывает ограниченные словесные шаблоны: аналог, исходную позицию, количество в штуках, город и условия покупки. Для неизвестного запроса предлагает поддерживаемые действия. Это детерминированная логика интерфейсного сценария; OpenAI, API и backend не вызываются.

Выбор аналога обновляет предложение, сохраняя корзину без изменений. В отдельном диалоге пользователь видит товар, итоговое количество, склад и сумму. Только «Подтверждаю добавление» сохраняет комплект в `localStorage` с ключом `kontur-design-cart-v1`. Повторное подтверждение заменяет количество указанным, не прибавляет его ещё раз.

Подтверждение доступно только для поддерживаемого аналога и целого количества от 1 до доступного остатка. Максимум ввода — 999. Исходный конфликтный товар и товар с номиналом 100 А не становятся подтверждённым решением запроса на 160 А. Корзина содержит одну позицию и открывается по `/cart`; «Новый подбор» сохраняет уже подтверждённую корзину.

Проверка остатков и суммы здесь выполняется в браузере на учебных константах. При интеграции её окончательное выполнение, изоляция сессий и идемпотентность переходят на сервер по контракту. Локальное хранилище концепта не является механизмом production-корзины.

## Адаптация и обратная связь

На ноутбуке боковая навигация сужается до иконок; при ширине до 820 px панель комплекта переходит под переписку. До 560 px навигация становится нижней, карточки каталога выстраиваются в одну колонку. Минимальная ширина текущего макета — 360 px.

Есть отдельные состояния пустой корзины, пустого поиска, нехватки остатков, выбранного аналога и подтверждённого комплекта. Изменения сопровождаются короткими уведомлениями. Диалоги используют нативный `<dialog>`, поля и кнопки с иконками имеют доступные названия; для клавиатуры предусмотрены видимые состояния фокуса. Учитывается `prefers-reduced-motion`. Это описание реализованных приёмов, не заявление о проведённом полном аудите доступности.

Исторические изображения отдельного дизайн-сценария: [настольный экран](assets/kontur-design-desktop.png) и [мобильный экран](assets/kontur-design-mobile.png).

Проверки предыдущего дизайн-сценария приведены в конце документа; они не доказывают работу серверной корзины или LLM.

## Сборка и лицензии

Установка и запуск описаны в [README](../README.md). `npm run build` сначала запускает проверку TypeScript, затем Vite; итоговый `web/dist` включается в репозиторий. Шрифты Fontsource входят в локальную сборку, внешние CDN в runtime не используются.

Версии и поля лицензий проверены по установленным `package.json` в `web/node_modules`; у Lucide и пакетов шрифтов также присутствуют файлы `LICENSE`.

## История проверки дизайн-прототипа · 23.09.2026

- Чистый локальный Git-клон: `npm ci`, `npm run build` — успешно; пересборка не изменяет закоммиченный `web/dist`.
- Playwright: выбор аналога, отмена подтверждения без изменения корзины, подтверждение 10 × 61 500 = 615 000 ₸, сохранение после перезагрузки.
- Количество выше остатка блокирует подтверждение; смена склада и количество/город в сообщении пересчитывают предложение. Проверены поиск, пустой результат, неподходящий номинал и закрытие диалога Escape.
- Ширины 360, 390, 820, 1024 и 1440 px проверены на горизонтальное переполнение; основной сценарий пройден на телефоне и компьютере.
- В production-сборке проверено пять последовательных подтверждений без дублирования количества; внешний сетевой доступ заблокирован, внешних запросов и ошибок JavaScript не было.
- После синхронизации с backend проверены `uv run hack seed`, `uv run hack serve`, `/api/health` и весь сценарий корзины через FastAPI на порту 8000.
- Копии лицензий шрифтов, React и Lucide находятся в `web/public/licenses/` и входят в сборку.

Эта историческая проверка относится к учебному интерфейсному концепту, который теперь открыт по `/?view=preview`. Его корзина остаётся в `localStorage`. Основной каталог `/` и `/?view=catalog` подключён к SQLite через API; его проверки перечислены отдельно выше.
