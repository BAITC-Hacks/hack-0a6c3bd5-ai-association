## Команды pip из README

Из корня свежего клона на macOS/Linux с Python 3.12:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m app.cli seed
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В проверке использовались имя окружения `.venv-pip` и свободный порт 8004. `DEMO_MODE=1` включён по умолчанию. Перед первым прямым запуском uvicorn нужен `seed`; команда `uv run hack serve` сама создаёт отсутствующую БД. Повторный `seed` для обычного запуска не требуется.

## Короткий чеклист Даниялу

1. **Windows 11, свежий клон.** В новой папке PowerShell выполнить команды ниже, без `.env` и ключей. Проверить `/api/health` (`demo_mode=true`), главную страницу и сценарий [DEMO.md](DEMO.md): конфликт блокирует предложение; после исключения строки и явного подтверждения корзина содержит 2 шт / 122 000 ₸ и сохраняется после перезагрузки.

   ```powershell
   git clone https://github.com/BAITC-Hacks/hack-0a6c3bd5-ai-association.git kontur-h4-check
   cd kontur-h4-check
   uv sync --frozen
   uv run hack serve --port 8004
   ```

   Для этого процесса адрес приложения — `http://127.0.0.1:8004`; в шагах DEMO.md заменить порт 8000 на 8004.

2. **Живой чат.** В отдельном чистом клоне локально настроить `DEMO_MODE=0`, свой `OPENAI_API_KEY` и доступный `OPENAI_MODEL`, затем перезапустить сервер. Модель должна поддерживать используемые в `app/llm.py` Responses API structured outputs и `temperature=0`; для следующего шага — также изображения. Отправить новый запрос, например «Проверь сведения о DEMO-160-AVAILABLE для проверки H4 [новая метка времени]». В ответе `POST /api/chat` зафиксировать **`answer_source=openai`**; `fixture` или `rules` не подтверждают успешный живой вызов. Корзина от информационного запроса не меняется.
3. **Живой OCR.** В этом же чистом клоне загрузить новый JPEG с собственными читаемыми строками спецификации, которого нет среди fixtures и в локальном кэше. Проверить успешный `POST /api/uploads` и совпадение распознанных артикула, количества и единиц с изображением. `sample.jpg` для этой проверки не подходит: он использует записанный результат. В ответе загрузки нет поля `answer_source`; доказательство — новый файл без fixture/кэша, успешный ответ и сверенные строки. `OCR_UNAVAILABLE` означает, что живой OCR не прошёл.
4. **Вернуть деморежим.** Установить `DEMO_MODE=1`, перезапустить сервер, проверить health и поставляемый образец повторно. Записать commit, ОС, модель, статусы запросов и результат; ключи, `.env`, cookie и полные сетевые дампы в отчёт не включать.
