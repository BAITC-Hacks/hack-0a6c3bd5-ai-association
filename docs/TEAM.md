# Совместная работа над «Контуром»

Проект: консультант ekt.kz — наличие, характеристики, сертификаты, аналоги, условия покупки и корзина только после явного подтверждения; отличие — выявление противоречий в каталоге с указанием источников.
Сначала прочитайте `AGENTS.md`, затем `docs/SPEC.md` и `docs/API-CONTRACT.md`. Стартовый промт A — `docs/DANIYAL-H1.md`; эта памятка фиксирует организацию совместной работы.
Репозиторий: https://github.com/BAITC-Hacks/hack-0a6c3bd5-ai-association — оба работают в `main`, каждый под своим аккаунтом.
Даниял (Windows 11), зона A: `app/`, `data/`, `fixtures/`; backend, агент, импорт каталога. Файлы зависимостей и запуска закрепляем за A при согласовании H1.
Мовсар (macOS), зона B: `web/`, `docs/`, `README.md`; интерфейс, интеграция, сборка `web/dist`, документация и демо. Общий `PROGRESS.md` ведёт B по результатам обоих.
Windows PowerShell: `git clone https://github.com/BAITC-Hacks/hack-0a6c3bd5-ai-association.git`, затем `cd hack-0a6c3bd5-ai-association`; если клон уже есть, откройте его. Проверьте свои `git config user.name` и `git config user.email`.
Перед работой: `git status`, затем при чистом рабочем дереве `git pull --rebase origin main`. После проверки своей задачи: `git add` только конкретных своих файлов, `git commit`, `git pull --rebase origin main`, `git push origin main`. При конфликте согласуйте изменения; force push не используем.
Каждый час: A отправляет проверенный результат к :50, B получает его, проверяет интеграцию и отправляет свой результат с записью в `PROGRESS.md` к :55. Формат коммита: `H1: краткое описание результата`.
У каждого своя сессия Codex в своём клоне. Перед новой задачей обновляйте Git; сообщайте партнёру хэш коммита и изменения API. `.env`, API-ключи, промокоды и локальная БД в Git не попадают; DEMO_MODE=1 работает без ключей.
