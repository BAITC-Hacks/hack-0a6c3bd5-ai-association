# Контур — проверяемая закупка электротоваров

Консультант для ekt.kz: помогает найти товар, сопоставить характеристики и наличие, увидеть противоречия и собрать корзину после явного подтверждения.

**Текущая версия H2:** интерфейс работает с серверным чатом, предложениями и корзиной FastAPI + SQLite. Каталог содержит 13 позиций: 10 сохранённых карточек API ekt.kz и 3 синтетические позиции для демосценариев. Это локальный снимок, а не полный или живой каталог магазина. Основной сценарий и обработка ошибок проверены в браузере на компьютере и телефоне.

![Чат и предложение «Контура»](docs/assets/kontur-chat-desktop.png)

## Запуск без Node.js и API-ключей

Нужны Python 3.12 и uv. Из корня клона:

```text
uv run hack serve
```

Откройте `http://127.0.0.1:8000`. При первом запуске создаётся `data/app.db` из CSV, FastAPI отдаёт закоммиченный `web/dist`. По умолчанию `DEMO_MODE=1`: ответы берутся из fixtures и правил, внешние ключи и сеть для работы не нужны. Первичная установка зависимостей требует сети.

Для явной загрузки поставляемого набора используйте `uv run hack seed`; при обычном повторном запуске это не требуется.

## Основной сценарий

1. На `/` выберите склад и отправьте «Проверь товар 200300285_». Ассистент покажет сведения и паспорт проверки: описание содержит 160 А, характеристика — 250 А.
2. Отправьте «Подбери 2 штуки на 160 А». Результат содержит реальные записи локальной SQLite; синтетические позиции обозначены как учебные.
3. Укажите точный артикул и количество, например «Добавь 2 шт DEMO-160-AVAILABLE». Сервер подготовит предложение; корзина пока не изменится.
4. Нажмите «Проверить и подтвердить». В окне проверки видны итоговые количества, склад и сумма. После явного подтверждения сервер повторно проверит предложение и изменит корзину.
5. Откройте `/cart`. Состав хранится в SQLite и сохраняется после обновления страницы в той же анонимной сессии.

Для изменения количества или удаления строки используйте действия корзины либо запрос с артикулом, например «Установи 3 шт DEMO-160-AVAILABLE» или «Удали DEMO-160-AVAILABLE». Они готовят новое предложение и требуют подтверждения. Количество в предложении означает итог в корзине, а не дополнительную прибавку.

Текстовое подтверждение в интерфейсе вызывает endpoint подтверждения с ID показанного предложения; предложение другой вкладки не может подменить его. Подтверждение действует только в своей сессии и складе; решение модели не разрешает изменение корзины. Устаревшая цена, недостаточный остаток или изменение контекста требуют нового рассмотрения. Повтор запроса использует тот же UUID и не дублирует операцию.

## Каталог и происхождение данных

`/?view=catalog` открывает серверный поиск по названию и артикулу с пагинацией по 6 товаров. Склады — Астана (название источника «Нур-Султан»), Алматы и Шымкент. Кнопка поиска и `Ctrl+K` / `⌘K` переводят фокус в каталог. «Обсудить товар» передаёт выбранный артикул в чат.

| Поиск по артикулу | Что есть в снимке |
| --- | --- |
| `200300285_` | 64 920 ₸; Астана — 8 шт., Алматы — 5, Шымкент — 2; общий остаток — 23; конфликт 160/250 А |
| `030300435_` | 53 ₸; Астана — 0 шт., общий остаток — 10 310 шт. |
| `000-DEMO-UNKNOWN` | Учебная позиция с неизвестными ценой, минимумом и остатками |

Карточка сохраняет описание и свойства раздельно, показывает локальный и общий остатки, минимум, документы и дату снимка. `null` — «Нет данных», а 0 — подтверждённое отсутствие. Отсутствующие изображения и сертификаты обозначены текстом.

У текущего набора `source=demo_fixture`; у 10 сохранённых карточек есть `source_url` ekt.kz и время `captured_at`. Единицы демо заданы явно через `demo.unit_override`. Наличие не обещается актуальным на момент просмотра. Внутренний ID `515291` не является поисковым артикулом: используйте `200300285_`.

## Сессия, режимы и ограничения

- Анонимная сессия создаётся сервером через HttpOnly cookie, без регистрации. Корзина хранится в SQLite; другая сессия получает собственную корзину.
- История сообщений текущего интерфейса хранится в памяти и исчезает после перезагрузки; серверная корзина сохраняется. Данные товаров и корзины поступают из API; автономный набор интерфейса удалён.
- Старый адрес `/?view=preview` открывает настоящий серверный чат. Отдельного автономного дизайн-демо в навигации нет.
- Бейдж ответа отражает `answer_source` API: fixtures, правила или OpenAI. Live-режим реализован через `app/llm.py` с structured outputs, таймаутом и fallback; внешний вызов с настоящим ключом в этой проверке не тестировался.
- Корзина имеет `scope=local_demo`: это корзина прототипа. Заказ, оплата и резервирование в ekt.kz не выполняются. Backend загрузки документов H3 уже добавлен; подключение загрузки к интерфейсу — следующий этап.
- Ошибки запуска сессии и запросов показывают повтор. Клиент ждёт GET до 10 секунд, POST до 40 секунд; неопределённый результат операции повторяется с прежним идентификатором.

## Разработка интерфейса

Нужны Node.js 22.12+ и npm. Оставьте backend запущенным командой выше; во втором терминале из корня клона:

```text
cd web
npm ci
npm run dev
```

Откройте адрес Vite, обычно `http://127.0.0.1:5173`. Запросы `/api` проксируются на порт 8000. Для сборки в папке `web` выполните `npm run build`: TypeScript проверяется, результат записывается в `web/dist` и включается в Git. Готовую сборку просматривайте через FastAPI на порту 8000. Шрифты и assets локальны, CDN в runtime нет.

## Проверки и материалы

Backend после объединения H2/H3: **186 тестов успешно прошли в чистом клоне**. Playwright: конфликт 160/250 А, подбор, отмена и подтверждение, изменение количества, удаление, сохранение корзины после перезагрузки и смена склада. Проверены нулевые/неизвестные остатки, устаревшее предложение (409), потеря ответа после серверной записи и повтор с тем же UUID, некорректный JSON, блокировка текстового подтверждения скрытого предложения и подмены из другой вкладки. Мобильный экран 390 px без горизонтального переполнения. Чистый клон на macOS запускается по README без ключей. В Playwright весь сценарий проходит с заблокированными внешними обращениями, без ошибок JavaScript; сессии изолированы. Повторная сборка совпадает с `web/dist` в Git. После объединения с backend H3 повторно проверены запуск, мобильное подтверждение и сохранение корзины. Windows 11 ещё должен проверить второй участник.

Frontend: React + TypeScript + Vite + Tailwind, собственные CSS-компоненты, Lucide, локальные Manrope и IBM Plex Mono. Backend: Python 3.12 + FastAPI + SQLite.
